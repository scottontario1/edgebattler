# Working rules for this project

Read AGENTS.md, docs/DEVELOPMENT.md and docs/CURRENT_GAPS.md for durable direction, system-first execution and the current backlog. Historical overhaul task lists are evidence of earlier passes.

- Stack: Three.js + Vite, plain JS modules in `src/`. Terrain, props and portraits are procedural (primitives + SVG). All unit models are ours, built on the universal humanoid: the named heroes Brenna and Dreg (`build_heroes.py`) and the unnamed recruit classes pikeman / archer / cavalier (`build_recruits.py`), all under `public/models/env/` (credit any new third-party assets in `CREDITS.md`). Environment GLBs in `public/models/env/` are generated by our Blender scripts; edit the script, not the GLB. Ask before adding other binary assets.
- Read `GAME.md` before starting a feature and build one milestone slice at a time.
- After each visible change: start the `vite` preview (`.claude/launch.json`), screenshot it, and check the console for errors before reporting done.
- Hover and click the affected units/tiles to verify interactions, not just the first frame.
- Commit after every working slice.
- Give sizes, colors and speeds as concrete numbers. Tiles are 1 world unit; the map is 16 x 12 (`src/map.js` LAYOUT).

## Layout
- `src/map.js`: terrain layout, tile meshes, props (trees, mountains, villages, castles, bridge), water and flag animation
- `src/textures.js`: high-res canvas textures (grass, dirt, rock, stone, wood, riverbed, water normal map)
- `src/main.js`: bootstrap only: preloads assets (`loadPaint()`; add future preloads here) then dynamically imports `src/game.js`, so the terrain painters see loaded textures
- `src/terrain.js`: terrain registry (`TERRAIN`: name, def/avo, block height, atlas `ground` class, props) and `parseLayout()` validation. Add a terrain type here first
- `src/maps/*.js`: a map is plain data (ASCII `layout` over the registry + per-map features such as `hills`); `src/map.js` builds geometry and painting from the active map (`river_ford.js`). Roads, the river island, rocks and village plots are still coded in `map.js`; moving them into the map data is the next step toward multiple maps
- `src/paint.js`: loads the painted detail maps (`public/textures/painted/`, made by `tools/assets/prep_terrain_textures.py` from the CC0 watercolor pack in `art/textures/watercolor/`: neutral-grey soft-light maps) and `paintTile(set, n)`; `terrainAtlas()`/`riverTextures()` in `src/textures.js` blend them via `paintDetail(g, mask, tile, {px, span, offset, opacity, blend})`. New material family: add sources, list the set in `PAINT_SETS`, rerun the prep script
- `src/painterly.js`: `PainterlyPass` (Kuwahara, radius 2) after bloom; sprites are masked out (they sit on `MASK_LAYER` with a `userData.maskMaterial` cutout; the mask is depth-tested against the scene). P toggles it, `?paint=0` starts with it off
- `src/game.js`: renderer + post-processing (GTAO ambient occlusion, bloom, painterly filter, SMAA at 1x CSS resolution); 2048px shadows refreshed once per rendered frame, 60 FPS cap, and hidden-tab pause; H toggles HD
- `src/units.js`: roster (Brenna, Dreg + recruits from the `RECRUIT` class templates) and procedural low-poly figures (fallback; M toggles)
- `src/models.js`: class -> model table (`MODEL_SPECS`) and `buildHero()`: matte standard materials for cloth/fur/skin at roughness 0.9+, hard cel-shaded polished `MeshToonMaterial` metals, per-unit skin/hair/iris/brow colours, faction `cloth` recolour, unlit `ink` and decal materials (the outline and faces are built into the GLBs), `HERO_SCALE`, procedural idle and ready pose; `buildModel()` seats the cavalier rider on the horse
- `src/sprites.js`: the sprite direction (`docs/asset-pipeline-plan.md`): every class (Brenna, Dreg, pikeman, archer, cavalier) is an illustrated 2D cutout from `design_assets/*_sprite.png` on upright, alpha-tested, unlit camera-facing planes (stretched by 1/cos(tilt), picking follows the alpha mask). `tools/assets/prep_sprites.py` trims/downscales them into `public/sprites/` + `manifest.json` (foot anchor, crop offsets, world size). Scale is anatomical: each entry gives the head-top row and the world foot-to-head height (recruits share `STAND_RECRUIT`, heroes are taller); the cavalier is matched to the infantry's head size, and weapons/horses come out at the size they were drawn. Each sprite gets a contact shadow sized from its foot span; sources are never edited; recruit classes get a `_red` variant (blue cloth hue-shifted to crimson) for the red army. `?sprites=0` shows the old 3D models for comparison
- `src/portraits.js`: SVG bust portraits generated from each unit's `look`
- `src/ui.js`: HUD state and behaviour (selection, planning cards, deploy, spells, combine, Resolve battle, range/danger overlays, targeting). It builds plain data models and hands them to the template modules in `src/ui/`; it owns no HUD markup beyond `index.html`. Styles use the tokens at the top of `src/style.css` (base layout only: panels, objective, turn, actions, dock, hint); portrait and short-landscape layouts reflow via media queries. `insets()` in `src/camera.js` follows the measured tray via `trayInset()`
- `src/ui/*`: one module + stylesheet per HUD component, each with its own `@media` blocks for landscape (L), short landscape (S, `max-height: 500px`) and portrait (P): `tray` (planning tray shell, collapse, battle lock, publishes `--tray-h`), `hand` (hand/reserve cards, detail bar, skill loadouts), `upgrade` (queued spells, combine dialog), `unitpanels` (unit card, forecast, inspect sheet, roster, terrain chip), `feed` (phase pill, banners, floating numbers, round-results log), `plates` (on-map unit plates and village/keep pennants, DOM projected from the scene), `icons` (shared inline-SVG vocabulary), `util` (`esc`, `uniqueIds`). Templates are pure functions of plain data; the `data-*` attributes they emit are the contract with `ui.js`. Type floor 10px (11px for anything the player must read), controls 32px (44px under `pointer: coarse`)
- Dev hooks: `window.__ui` = `{ state, feed, plates, commands, refresh, territory, units, cardState, skillLoadouts }` for driving HUD states in screenshots. Design backlog, task briefs and before/after evidence: `docs/design_overhaul/`
- `src/match.js`: the match controller, the single owner of game state and rules, shared by the browser and the simulator. Planning changes go through `apply({ type, faction, ... })` (recruit, deploy, withdraw, move, stance, abilities, facing, spell, cancelSpell, equip, transfer, combine); `resolveRound()` runs spells, abilities, simultaneous movement/combat (`battle.js`), deaths, captures, the end check (either side wins by holding the other's keep or destroying its army; optional `maxRounds` draw) and the next round's refresh, and returns presentation batches. `RULES` holds the pacing constants. Pure data: `src/board.js` (grid) and `src/roster.js` (unit templates) keep Three.js out of it
- `src/ai/commander.js`: AI commanders that plan one side through `match.apply` (so AI moves log and replay like a human's): `passive`, `greedy` (units only), `heuristic` (all card types, stances incl. marching on the enemy keep, withdraw, combine; weights in `DEFAULT_PARAMS`). `runCommander(match, faction, name, params)`
- `src/log.js`: JSON Lines game log (header, action, round, summary, result entries), `playLog()` (browser; dev server writes `logs/play/*.jsonl` through the `/__log` plugin in `vite.config.js`), `replay(entries)` determinism check. URL flags: `?seed=N`, `?red=<policy>` (default greedy), `?blue=` / `?auto=<policy>` for AI-vs-AI in the browser, `?speed=4`
- Experiments (branch sim/combat-experiments): `experiments/` holds opt-in candidate cards/abilities (`candidates/`), scenario suites (`combat/`), experiment maps (`maps/`, activated with `setMap()` in `src/board.js`) and baseline drivers; results and reports in `docs/experiments/`. None of it is active in the game.
- Simulator: `npm run sim -- --games 200 --blue heuristic --red greedy --swap --verify` writes one JSONL per game and `summary.csv` to `logs/sim/<run>/`; `npm run sim:report -- logs/sim/<run>` prints win rates (95% intervals), game length, end reasons and per-side averages. `logs/` is git-ignored
- `src/combat.js`: weapon table, combat forecast (hit/crit/damage/doubling, weapon triangle) and `resolve()` (dice, strike order; does not mutate hp: the caller applies each strike as it animates it)
- `src/rules.js`: move costs and `computeRange()` (reachable tiles, attackable tiles, per-enemy best stand tile, `pathTo()`), shared by the match, the UI and the AI. `src/ai.js`: legacy manual-turn AI (`chooseAction()`), unused by the round flow. `src/ui.js` `resolveBattle()` calls `match.resolveRound()` and plays its batches back (HP bars show `displayHp` during playback); unit animation (`moveAlong`, `lunge`, `shake`, `die`) in `src/units.js`. Controls: click a unit, click a blue tile to move it (planning move), S stance, W withdraw, Enter/Resolve battle, R restart after the end
- `src/camera.js`: ortho camera (40° tilt, 52° in portrait) framed to the space the HUD leaves free; wheel/pinch zoom, drag pan
- `tools/blender/`: headless Blender scripts that build `public/models/env/*.glb`. `build_env.py` = stone bridge + cliff backdrop; `build_buildings.py` = castle + cottages; `humanoid.py` = the universal humanoid standard for the whole cast (~3.75 heads / 1.18 tall, slender jointed limbs, defined waist, heeled fitted boots, dynamic ready stance solved with two-bone IK, anime head whose face is flat decal polygons (`face_decals`: almond sclera, gradient iris, pupil, highlights, flicked upper lash, brows, mouth; no eye spheres), capsule limbs so sleeves/trousers/greaves bridge every joint (no ball joints), a baked inverted-hull `ink` outline (`add_ink`, single-sided material), node hierarchy `hero > hips > torso > head, arm_l > fore_l, arm_r > fore_r, cape; hips > thigh > shin`; read its docstring before building any new character); `build_heroes.py` = Brenna (paladin) and Dreg (berserker) built on it to the sheets in `design_assets/` (layered tapered-lock hair over a solid cap with vertex-colour root-to-tip gradients, beard fused to the jaw, oversized pauldrons/cape, layered fur planes, weapons ~1.25x); animated as rigid parts by `buildHero()` in `src/models.js`; `build_recruits.py` = the unnamed recruit classes (pikeman with pike, hooded archer with longbow and quiver, seated cavalier with lance and shield) reusing `build_heroes.py` helpers; each class is one GLB shared by both armies (faction colour via the `cloth`/`clothdark` materials); `build_units.py` = barded cavalry horse (skin-modifier body, face details ray-snapped onto the head); `common.py` = shared helpers. The scripts also run in a live Blender over Blender MCP (`runpy.run_path`; pop `common` from `sys.modules` after editing it), where `reset()` only clears the scene so the MCP add-on stays loaded. Blender material names (stone, roof_faction, banner, window…) are swapped for game materials in `buildingMaterials()` in `src/map.js`. Rebuild with `C:/Users/scott/tools/blender-5.2.1-windows-x64/blender.exe -b --factory-startup -P tools/blender/build_env.py`. Keep `LAND_TOP`/`WATER_Y` in sync with `src/map.js`.
- Screenshots: `node tools/shot.mjs out.png 1280 800 [query]` (headless Chrome, device emulation, `STEPS` env for scripted input). Query flags: `zoom`, `focus=c,r`, `select=id`, `act=attack,inspect,danger,grid`, `target=id`, `place=id:c,r`. Before/after captures live in `docs/redesign/`.
- Dev only: `window.__game` exposes `{ THREE, scene, camera, renderer, units }` for console inspection.

- Palette (sRGB, in `mats()` of `tools/blender/build_heroes.py` and mirrored in `src/models.js`): royal blue `#1A4FA0` / crimson `#A8231C` faction cloth, leather `#5C381E`, polished steel `#B8C4D6` with gold `#F0B830` / brass `#D9A441` trim. Blender materials carry these defaults so a GLB looks right in any viewer; the game re-tints by material name.

## SYS-01 ability implementation
- src/abilities.js owns approved kits, selection validation, energy refresh, fixed-phase activations, movement allowance and authoritative cardinal facing. src/battle.js locks final-path facing before recovery/enhancements/strikes, and selects legal targets before ranking.
- src/ui/abilities.js and abilities.css own the friendly planning editor, draft picks, same-class group application and facing controls. Gold overlays show current side/back tiles; arrows use authoritative facing, not sprite orientation.
- npm run test verifies rule contracts. With Vite running, node tools/verify-abilities.mjs captures normal multi-round planning; --mobile checks narrow layouts; --combat uses an explicitly controlled combat fixture. tools/shot.mjs exits nonzero on page or scripted-evaluation errors. Stop the server afterward.
- Log schema 3 records full hand state, cycle allowance, refund metadata and battle state; replay validates actions, events, summaries and results. Schema 1/2 logs are intentionally rejected after the rules change.

## SYS-02 cycling implementation
- src/cards.js owns previewCycle/cycleCard, shared cyclesRemaining, same-type/rarity/grade weighted replacement, recipe pricing and refund overflow income. src/match.js exposes the logged cycle action with source hand/bench and id; sideSummary includes full hand state. src/roster.js creates fresh grade-adjusted recruits; src/upgrades.js sums costPaid and matches rarity separately from stars. Preserve investment through deployment and withdrawal.
- src/ui/hand.js and ui/tray.js show the cycle allowance and previews; src/ui.js sends authoritative actions. Bench cycling requires a free hand slot. All current cards are common; do not invent rarity rates or population progression.
- npm run test covers cycling and SYS-01 contracts. With Vite running, node tools/verify-cycling.mjs checks desktop; --mobile checks portrait and short windows. Evidence: docs/SYS02_VERIFICATION.md. Stop verification servers. Simulator reports hand/bench cycles and Supply refunds; DEFAULT_PARAMS.cycling=false isolates commander cycling behavior.
